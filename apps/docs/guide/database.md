# Database

Agent Zero's runtime is deliberately persistence-free. The repository contains exactly one database — Postgres, used by the dashboard's authentication session store — and exactly one place that connects to it.

## One connection, one route

`apps/dashboard/server/auth.config.ts` mounts Better Auth at `/api/auth/**` and is the only route in the app that resolves `AUTH_DATABASE_URL` and the signing secret. Every other route reaches storage exclusively through the `KeyValueStorage` contract (see below). This makes the persistence surface reviewable: nothing else in the repository can open a database connection.

## Schema with Drizzle

The session store's schema is declared in [Drizzle](https://orm.drizzle.team) (`packages/auth/src/schema.ts`) rather than generated by Better Auth's own migration CLI, so `user`, `session`, `account`, and `verification` are reviewable, checked-in SQL under `packages/auth/drizzle/` like any other schema change. `drizzleAdapter` binds the Better Auth model layer to that schema; nothing outside `packages/auth` queries the tables directly.

## Setup

Point `AUTH_DATABASE_URL` at a Postgres database, then apply the schema once before the first run:

```bash
aube --filter @agent-zero/auth run db:migrate
```

`db:generate` only needs to run again after editing `packages/auth/src/schema.ts`:

```bash
aube --filter @agent-zero/auth run db:generate
```

## Task history is not in Postgres

Task history persists through a narrow `KeyValueStorage` contract backed by the ViteHub KV Runtime Helper (registered by the local `apps/dashboard/modules/vitehub.ts` Nuxt module): filesystem-backed `fs-lite` by default, with Cloudflare KV, Deno KV, or Upstash dropping in as driver configuration without touching application code.

Records are redacted before they are written and never contain review input or checkout paths, so task history cannot become a credential or filesystem leak.
